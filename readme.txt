ย้าย/สำรอง WordPress ทั้งเว็บ (ฐานข้อมูล + ไฟล์) เป็นแพ็กเกจเดียว แล้วนำเข้ากลับ หรือส่งขึ้น S3-compatible storage ได้โดยตรง

== Description ==

InsightX Backup เขียนขึ้นใหม่ทั้งหมดโดย InsightX ไม่ได้ fork หรือดัดแปลงจากปลั๊กอินอื่น — engine ทุกส่วน (archive format, dump/import ฐานข้อมูล, serialized-safe find & replace, S3 client) เขียนขึ้นใหม่จากศูนย์

**คุณสมบัติหลัก:**

* **ส่งออก (Export)** — แพ็กฐานข้อมูล + ทั้ง wp-content เป็นไฟล์ .wpress เดียว ดาวน์โหลดเป็นไฟล์ หรือส่งขึ้น S3 โดยตรง
* **นำเข้า (Import)** — อัปโหลดไฟล์ .wpress หรือนำเข้าจาก S3 โดยตรง กู้คืนไฟล์ + ฐานข้อมูล พร้อมแทนที่ URL/path/table-prefix อัตโนมัติ แบบ clean-then-restore
* **ข้อมูลสำรอง (Backups)** — ทุกครั้งที่ export จะถูกเก็บสำเนาไว้ในเครื่องเสมอ ดูรายการ/กู้คืน/ดาวน์โหลด/ดูเนื้อหา/ลบได้จากหน้าเดียว
* **การเชื่อมต่อ Storage** — Amazon S3, Minio, Garage, Cloudflare R2, DigitalOcean Spaces, Google Cloud Storage หรือปลายทาง S3-compatible อื่นๆ พร้อมกันหลายเจ้า
* **Backup อัตโนมัติ** — ตั้งเวลา export อัตโนมัติผ่าน WP-Cron (รายวัน/รายสัปดาห์/รายเดือน)
* **Find & Replace** — แทนที่ข้อความในฐานข้อมูลตอน export ได้หลายคู่
* **ศูนย์รีเซ็ต (Reset Hub)** — ล้างปลั๊กอิน / รีเซ็ตธีม / ล้างคลังสื่อ / รีเซ็ตฐานข้อมูล / รีเซ็ตทั้งเว็บไซต์ พร้อมยืนยันด้วยรหัสผ่านก่อนทำรายการทุกครั้ง
* **WP-CLI** — `wp isx export` / `wp isx import <file>` / `wp isx providers` / `wp isx cleanup-uploads`

> ⚠️ ไฟล์ .wpress ของปลั๊กอินนี้เป็นฟอร์แมตของ InsightX เอง ไม่ compatible กับไฟล์ .wpress ของ All-in-One WP Migration แม้ใช้นามสกุลเดียวกัน

== Installation ==

**ดาวน์โหลด zip จาก GitHub**

1. เข้า `https://github.com/InsightX-th/insightx-backup`
2. เมนู Releases เลือกเวอร์ชันล่าสุด ดาวน์โหลด `insightx-backup-vX.X.X.zip` จากส่วน Assets
3. ไปที่เว็บ WordPress ปลายทาง → Plugins → Add New → Upload Plugin
4. เลือกไฟล์ zip → Install Now → Activate Plugin

**ติดตั้งตรงจากโฟลเดอร์ (dev/local)**

1. วางโฟลเดอร์ `insightx-backup` ไว้ที่ `wp-content/plugins/`
2. เปิดใช้งานปลั๊กอินจากเมนู Plugins
3. เมนู InsightX Backup จะปรากฏใน sidebar ของ wp-admin

**ความต้องการของระบบ:** PHP 7.4+, ส่วนขยาย cURL/zlib/openssl

== Changelog ==

= 0.1.17 =
* **แก้ URL ที่ยังชี้โดเมนเดิมหลังนำเข้า** — เดิมระบบค้นหา URL เก่าแบบตรงตัวรูปเดียว ซึ่งจับได้แค่เศษเสี้ยวเดียวของที่มันอยู่จริงในฐานข้อมูล เพราะแต่ละปลั๊กอินเก็บ URL คนละรูปแบบ ตอนนี้แจกแจงครบทุกรูปแบบแล้วชี้กลับมาที่โดเมนที่เว็บปลายทางตั้งไว้จริง
* **รองรับ JSON ที่ escape slash (`https:\/\/domain`)** — Elementor และ page builder อื่นเก็บทั้งหน้าเป็น JSON แบบนี้ในตาราง postmeta บนเว็บที่สร้างด้วย Elementor นี่คือเนื้อหาเกือบทั้งเว็บ และการค้นหาแบบเดิมไม่ match แม้แต่รายการเดียว (ตรวจกับเว็บจริง: 2,930 แถวเก็บแบบ escape, 0 แถวเก็บแบบธรรมดา)
* **รองรับ percent-encoded, protocol-relative (`//domain`) และ www/non-www** — URL ที่ฝังใน query string, redirect, oEmbed cache และลิงก์รูปแบบเก่าในธีม
* **แก้ลิงก์ `http://` ที่ค้างจากยุคก่อนย้าย SSL** — ปลั๊กอินอย่าง Really Simple SSL แก้เฉพาะตอนแสดงผล ไม่เคยแก้ข้อมูลที่บันทึกไว้ ลิงก์ `http://` ของโดเมนตัวเองจึงยังอยู่ในฐานข้อมูล ตอนนี้ถูกปรับให้ตรงกับ scheme ที่เว็บตั้งไว้ — นำเข้าทับโดเมนเดิมของตัวเองก็ช่วยแก้เรื่องนี้ได้
* **รองรับ URL แบบไม่มี scheme ใน HTML attribute** (`href="domain.com/page"`) โดยไม่แตะชื่อโดเมนที่อยู่ในข้อความธรรมดา
* **รองรับคลังสื่อที่ตั้งไว้นอก `wp-content`** — เว็บที่ตั้ง `upload_path`/`upload_url_path` เองจะถูกแทนที่ URL ให้ด้วย (แพ็กเกจที่ export ก่อนเวอร์ชันนี้ไม่มีข้อมูลส่วนนี้ จะข้ามไปโดยไม่ error)
* **รองรับ page builder ที่เก็บเนื้อหาเป็น base64** — WPBakery/Visual Composer, Oxygen, BeTheme, OptimizePress, Avada Fusion Builder จะถูกถอดรหัส แทนที่ URL ข้างใน แล้วเข้ารหัสกลับ ทำเฉพาะ builder ที่มีอยู่จริงในแพ็กเกจเท่านั้น และเฉพาะเมื่อข้อมูลผ่านการตรวจว่าเป็น base64 จริงและมี URL เก่าอยู่ข้างใน ถ้าไม่เข้าเงื่อนไขจะคืนค่าเดิมทุกไบต์ ไม่เข้ารหัสใหม่
* **แก้บั๊กแทนที่ซ้อน** — เดิมแทนที่ทีละคู่วนทับข้อความทั้งก้อน คู่หลังจึงไปเจอผลลัพธ์ที่คู่ก่อนหน้าเพิ่งเขียน ทำให้ URL เพี้ยนเมื่อโดเมนปลายทางมีโดเมนต้นทางเป็นส่วนหนึ่ง เช่น ย้ายไป staging ที่ต่อท้ายโดเมน (`a.com` → `a.com.staging.net` ได้ผลเป็น `a.com.staging.net.staging.net`) หรือย้ายเว็บเข้า subdirectory (`example.com` → `example.com/blog`) ตอนนี้แทนที่รอบเดียวจบ เลือกคู่ที่ยาวที่สุดในแต่ละตำแหน่ง
* ข้อมูล serialized ยังปลอดภัยเหมือนเดิม เพราะการแทนที่ทำบนค่าที่ unserialize ออกมาแล้ว ความยาว `s:NN:` ถูกคำนวณใหม่ให้เสมอ

= 0.1.14 =
* **นำเข้า (Import) ไม่ทับ license key ของปลั๊กอินอื่นอีกต่อไป** — เดิม import จะทับ `wp_options` ปลายทางทั้งตาราง ทำให้ license/การตั้งค่าของเว็บปลายทางหายหมด ตอนนี้ก่อน import จะเก็บค่าของเว็บปลายทาง (`siteurl`, `home`, การตั้งค่าปลั๊กอินนี้เอง, ฯลฯ) ไว้ก่อน แล้วเขียนคืนหลัง import เสร็จ — ปรับได้ผ่าน filter `isx_preserved_option_names` / `isx_preserved_option_prefixes`
* **รวมค่า Freemius license (`fs_accounts`) แทนการทับ** — ปลั๊กอินพรีเมียมที่ใช้ Freemius (เช่น ACF PRO) ที่ activate ไว้บนเครื่องปลายทางจะไม่โดนปิดใช้งานหลัง import อีกต่อไป
* **ไม่นำเข้า transient/session cache** — `_transient_*`, `_site_transient_*`, `_wc_session_*` ที่ผูกกับ domain เดิมจะถูกข้ามตอน import ป้องกัน cache สถานะ license เก่าทำให้ขึ้น invalid ทั้งที่ key อยู่ครบ
* **กัน option ไม่ให้โดนเปลี่ยนชื่อผิดตอน table prefix ต่างกัน** — option อย่าง `wp_rocket_*`, `wp_mail_smtp*` ที่ขึ้นต้นด้วย `wp_` เฉยๆ (ไม่ใช่ table-prefixed จริง) จะไม่โดน rename จนปลั๊กอินหาไม่เจอ
* **เพิ่ม error handling ตอนเขียนแถวฐานข้อมูล** — ถ้า INSERT หลายแถวพร้อมกันล้มเหลว จะเขียนใหม่ทีละแถวแทน และ log ว่าแถวไหนล้ม (เดิมล้มเงียบทั้งก้อนโดย import ยังรายงานว่าสำเร็จ)
* หน้าความคืบหน้าของ export/import แสดงทศนิยม 2 ตำแหน่งแทนปัดเป็นจำนวนเต็ม กันแถบดูเหมือนค้างตอนอยู่ช่วงที่ % เต็มเดิมนานๆ

* **แก้ต้นเหตุที่แท้จริงของ "HTTP 404: The specified multipart upload does not exist"** — ที่แก้ไปใน 0.1.11 เป็นแค่อาการปลาย ตัวต้นเหตุคือปลั๊กอินเขียนไฟล์สถานะงาน (state.json) ทับตรงๆ ระหว่างอัปโหลด (ไฟล์ใหญ่ๆ เขียนนับพันครั้งต่อการอัปโหลดหนึ่งครั้ง) ถ้ามีอะไรมาอ่านไฟล์นี้พอดีจังหวะที่กำลังเขียน (เช่น ระบบล้าง upload ค้างที่ทำงานทุกครั้งที่เปิดหน้า wp-admin) จะเจอไฟล์ครึ่งเดียวและเข้าใจว่างานนั้นตายไปแล้ว แล้วไปสั่งยกเลิกการอัปโหลดที่ยังทำงานอยู่จริง ตอนนี้เขียนไฟล์แบบปลอดภัย (เขียนไฟล์ชั่วคราวแล้วสลับ) ไม่มีทางเจอไฟล์ครึ่งเดียวได้อีก

* เพิ่มปุ่ม **"ล้าง upload ที่ค้างบน Storage"** ในหน้าตั้งค่า Storage — เดิมมีแค่คำสั่ง WP-CLI ตอนนี้กดจากหน้าเว็บได้เลย เลือกได้ว่าจะตรวจ provider ไหน (ไม่เลือก = ตรวจทุกตัว) และถ้า provider ไหนตรวจสอบไม่ได้ (เช่น สิทธิ์ของ API token ไม่พอ) จะบอกชื่อ provider กับสาเหตุให้เลย แทนที่จะเงียบแล้วมีของค้างสะสมอยู่โดยไม่มีใครรู้
* เมื่อยกเลิก upload ที่ค้างไม่สำเร็จเพราะยังไม่ได้ตั้งค่า provider จะไม่ลืมรายการนั้นทิ้งอีกต่อไป — เก็บไว้ลองใหม่รอบหน้าแทนที่จะปล่อยให้ค้างถาวรแบบไม่มีใครตามเก็บ
* ตัดกล่อง "ข้อมูลระบบ" ออกจากหน้า Log บนหน้าจอ (ยังอยู่ในไฟล์ log ที่ดาวน์โหลดเหมือนเดิม)

= 0.1.11 =
* **แก้ข้อความ "HTTP 404: The specified multipart upload does not exist" ที่ขึ้นทั้งที่งานสำเร็จ** — หลังอัปโหลดขึ้น Storage เสร็จ ระบบไม่ได้ล้างรหัสอ้างอิงของการอัปโหลดนั้นทิ้ง ตัวจับงานค้างหรือปุ่มยกเลิกที่ทำงานทีหลังจึงไปสั่งยกเลิกการอัปโหลดที่จบไปแล้ว แล้วได้ 404 กลับมา (ซึ่งแปลว่า "ไม่มีรายการนั้นแล้ว" = สิ่งที่ต้องการอยู่แล้ว) ตอนนี้ถือว่าสำเร็จ และล้างรหัสอ้างอิงทุกครั้งที่การอัปโหลดจบ ไม่ว่าจะสำเร็จหรือไม่
* **บอกให้ชัดว่าไฟล์สำรองยังอยู่เมื่ออัปโหลดล้มเหลว** — ไฟล์ .wpress ถูกสร้างเสร็จและเก็บเข้าเมนู "ข้อมูลสำรอง" ตั้งแต่ก่อนเริ่มอัปโหลด การอัปโหลดที่ล้มเหลวจึงไม่เคยทำให้เสียไฟล์ที่ export ไปแล้ว แต่เดิมข้อความสีแดงไม่ได้บอก ทำให้ดูขัดกับไฟล์ที่โผล่อยู่ในรายการ ตอนนี้ระบุชื่อไฟล์ให้เลย (รวมถึงกรณีงานหยุดค้างด้วย)
* **แก้การรายงานว่าอัปโหลดสำเร็จทั้งที่ไฟล์ไม่ได้ขึ้นจริง** — ขั้นตอนรวมไฟล์ที่อัปโหลดเป็นชิ้นๆ เป็นคำสั่งเดียวที่ S3 ตอบ HTTP 200 มาก่อน แล้วค่อยแจ้งว่าล้มเหลวในเนื้อหาข้างใน (เพราะการรวมไฟล์ใหญ่ใช้เวลานานจนต้องส่ง header ออกไปก่อน) เดิมดูแค่รหัส 200 จึงบอกว่าสำเร็จทั้งที่ไม่มีไฟล์บน bucket
* **แก้การนำเข้าจาก Storage ที่โหลดไฟล์มาไม่ครบแล้วไม่รู้ตัว** — ตรวจขนาดไฟล์ที่โหลดได้เทียบกับที่เซิร์ฟเวอร์แจ้งมาทุกครั้ง
* แก้ปัญหาเว็บที่ใช้ WordPress เก่ากว่า 5.5 จะ error ทุกครั้งที่อัปโหลดไฟล์ใหญ่กว่า 5MB ขึ้น Storage (เรียกใช้ฟังก์ชันที่ยังไม่มีในเวอร์ชันนั้น)

= 0.1.10 =
* **แก้ด่วน: การลบข้อมูลสำรองเก่าบน Storage อาจไปลบของเว็บอื่น** — ฟีเจอร์ตัดไฟล์เก่าบน bucket ที่เพิ่มใน 0.1.9 กรองแค่ว่า "เป็นไฟล์ .wpress ที่อยู่ในโฟลเดอร์นี้" ซึ่งไม่พอ เพราะโฟลเดอร์เริ่มต้นบน Storage เป็นของ provider ไม่ใช่ของเว็บใดเว็บหนึ่ง การชี้หลายเว็บมาที่ credential เดียวกันจึงเป็นเรื่องปกติ ผลคือเว็บเล็กที่ตั้งเก็บไว้ 5 ไฟล์ อาจไปลบไฟล์สำรองของเว็บอื่นที่ใช้โฟลเดอร์เดียวกันทิ้ง ตอนนี้ตัดเฉพาะไฟล์ที่ขึ้นต้นด้วยชื่อโดเมนของเว็บตัวเองเท่านั้น
* **ผู้ที่อัปเดตเป็น 0.1.9 แล้วและเปิด backup อัตโนมัติแบบส่งขึ้น Storage ควรอัปเดตทันที** — โดยเฉพาะถ้ามีหลายเว็บใช้ bucket/โฟลเดอร์เดียวกัน

= 0.1.9 =
* **ตรวจสอบแพ็กเกจก่อนล้างเว็บ** — ตอนนำเข้า ระบบจะอ่านไฟล์ .wpress ทั้งไฟล์เพื่อยืนยันว่าครบถ้วนก่อน แล้วค่อยเริ่มล้างไฟล์เดิม เดิมตรวจแค่ 8 ไบต์แรก ไฟล์ที่ขาดไป 40% ก็ผ่าน กว่าจะรู้ว่าแพ็กเกจไม่ครบก็ตอนที่เว็บถูกล้างไปแล้ว เหลือทั้งเว็บเก่าที่หายและเว็บใหม่ที่กู้ไม่ได้ ตอนนี้แพ็กเกจที่ไม่สมบูรณ์จะถูกปฏิเสธตั้งแต่ต้น โดยเว็บปัจจุบันไม่ถูกแตะเลย
* **เพิ่มเมนู "ตรวจสอบไฟล์" ในหน้าข้อมูลสำรอง** — ตรวจความสมบูรณ์ของไฟล์สำรองได้ทุกเมื่อ ไม่ต้องรอถึงวันที่ต้องใช้จริงถึงจะรู้ว่าไฟล์เสีย
* **ลบข้อมูลสำรองเก่าบน Storage ตามจำนวนที่ตั้งไว้** — เดิมค่า "เก็บกี่ไฟล์" ของ backup อัตโนมัติมีผลกับไฟล์ในเครื่องเท่านั้น ไฟล์บน bucket สะสมไปเรื่อยๆ ไม่มีวันถูกลบ (เว็บที่สำรองวันละ 6GB คือค่าเก็บข้อมูลที่โตขึ้นทุกวันโดยไม่มีอะไรแจ้ง) ตอนนี้ตัดของเก่าบน Storage ตามจำนวนเดียวกัน และแตะเฉพาะไฟล์ที่ปลั๊กอินนี้สร้างเอง
* แก้การอ่านรายการไฟล์บน Storage ที่ได้ไม่ครบเมื่อมีเกิน 1,000 ไฟล์ (S3 ส่งมาทีละหน้า แต่เดิมอ่านแค่หน้าแรก) — สำคัญเป็นพิเศษเพราะการลบของเก่าตัดสินใจจากรายการนี้
* Backup อัตโนมัติที่ล้มเหลวจะไม่ลบไฟล์สำรองเก่าทิ้งอีกต่อไป — เดิมลบตามจำนวนที่ตั้งไว้ทุกครั้งแม้รอบนั้นจะไม่ได้ไฟล์ใหม่มาเลย และบันทึกสาเหตุที่ล้มเหลวไว้ในหน้า Log
* บอกชัดเจนเมื่อพื้นที่ดิสก์ของเซิร์ฟเวอร์เต็ม — เดิมงานที่เขียนไฟล์ไม่สำเร็จเพราะดิสก์เต็มจะเดินต่อเงียบๆ แล้วขึ้นว่า "ส่งออกเสร็จสิ้น" ทั้งที่ได้ไฟล์สำรองที่ไม่สมบูรณ์ หรือไม่ได้ไฟล์เลย (PHP ไม่แจ้ง error เวลาเขียนไฟล์ไม่ครบ) ตอนนี้ทุกขั้นตอนตรวจผลการเขียนจริงและหยุดพร้อมบอกพื้นที่ที่เหลือกับตำแหน่งไฟล์
* ครอบคลุมทั้งตอนส่งออก (รวบรวมรายการไฟล์ / ดัมป์ฐานข้อมูล / แพ็กไฟล์ / เข้ารหัส / เก็บลงข้อมูลสำรอง) และตอนนำเข้า (อัปโหลดไฟล์ .wpress / คลายบีบอัด / ถอดรหัส / กู้คืนไฟล์ / เตรียมไฟล์กู้คืนจากเมนูข้อมูลสำรอง)
* แก้ไฟล์สำรองเสียหายแบบไม่รู้ตัวเมื่อไฟล์ต้นทางถูกแก้ไขระหว่างแพ็ก — ไฟล์ที่ถูกเขียนทับหรือหดลงกลางคัน (log, ไฟล์แคช, ปลั๊กอินที่กำลังอัปเดตตัวเอง) ทำให้ข้อมูลในแพ็กเกจเคลื่อน และไฟล์ที่เหลือทั้งหมดหลังจากจุดนั้นอ่านไม่ออก โดยระบบยังรายงานว่าสำเร็จ
* แก้กรณีเลือก "เข้ารหัสด้วยรหัสผ่าน" แล้วเข้ารหัสไม่สำเร็จ — เดิมจะได้ไฟล์สำรองที่**ไม่ได้เข้ารหัส**ในชื่อเดิมโดยไม่มีอะไรแจ้ง ตอนนี้แจ้งว่าล้มเหลวและลบไฟล์นั้นทิ้ง ไม่ทิ้งไฟล์ที่ไม่ได้เข้ารหัสไว้
* แก้กรณีกดยกเลิกจังหวะที่ export เพิ่งเสร็จพอดี แล้วหน้าจอขึ้นว่ายกเลิกทั้งที่ไฟล์สำรองถูกสร้างเรียบร้อยและอยู่ในรายการแล้ว
* ปรับสไตล์ปุ่ม "ยกเลิก" ระหว่างส่งออก

= 0.1.8 =
* แก้ปุ่ม "ยกเลิก" ระหว่างส่งออกกดแล้วไม่มีอะไรเกิดขึ้น — เว็บที่อัปเดตมาจากเวอร์ชันเก่าได้ปุ่มใหม่มาแต่ยังใช้ไฟล์ JS เก่าที่ค้างในแคชของเบราว์เซอร์ ซึ่งไม่รู้จักปุ่มนี้ ตอนนี้ไฟล์ JS/CSS จะบังคับให้เบราว์เซอร์โหลดใหม่ทุกครั้งที่ไฟล์เปลี่ยนจริง ไม่ต้องรอเลขเวอร์ชันขยับ
* แก้การกดยกเลิกตอนที่ระบบกำลังทำงานอยู่แล้วงานไม่หยุดจริง — ยังทำงานต่อเบื้องหลังทั้งที่หน้าจอบอกว่ายกเลิกแล้ว และไฟล์ระหว่างทางถูกลบทิ้งทั้งที่ยังเขียนอยู่ ตอนนี้ยกเลิกได้ทุกจังหวะ และหยุดภายในไม่กี่วินาทีแม้เว็บจะมีไฟล์เป็นแสนรายการ
* ยกเลิกระหว่างอัปโหลดขึ้น Storage จะปิดงานอัปโหลดที่ค้างใน bucket ให้เรียบร้อยเสมอ
* ถ้าหน้าเว็บหลุดจากงานที่กำลังทำอยู่ ปุ่มยกเลิกจะบอกให้รีเฟรชหน้า แทนที่จะเงียบไปเฉยๆ

= 0.1.7 =
* แก้ปัญหาดาวน์โหลดข้อมูลสำรองแล้วเบราว์เซอร์ขึ้นว่าไฟล์ใช้งานไม่ได้ ต้องไปโหลดจาก bucket แทน — โฟลเดอร์เก็บไฟล์สำรองถูกกฎความปลอดภัยของโฟลเดอร์แม่ปิดกั้นไปด้วย ทำให้เซิร์ฟเวอร์ปฏิเสธคำขอ (เจอเฉพาะบางโฮสต์ และบางครั้งเท่านั้น จึงดูเหมือนสุ่ม)
* การอัปโหลดที่เริ่มไว้แล้วไม่จบ (งานถูกยกเลิก เน็ตหลุด เซิร์ฟเวอร์ตายกลางทาง) จะค้างอยู่ใน bucket โดยยังไม่เป็นไฟล์จริง มองไม่เห็นในรายการไฟล์และลบผ่านหน้าเว็บของผู้ให้บริการไม่ได้ แต่ยังกินพื้นที่ ตอนนี้ปลั๊กอินยกเลิกให้เองทันทีทุกกรณี ไม่ต้องกดอะไร รวมถึงของที่ค้างมาจากก่อนหน้านี้และของที่มาจากเว็บอื่นที่ใช้โฟลเดอร์เดียวกัน
* งาน export ที่ค้างจะถูกปิดจริง แทนที่จะค้างอยู่ในระบบตลอดไป
* เพิ่มปุ่ม "ยกเลิก" ระหว่างส่งออก
* เพิ่มคำสั่ง WP-CLI `wp isx cleanup-uploads` (มี --to=<provider> และ --dry-run)

* แก้ปัญหาอัปโหลดขึ้น Storage ค้างนานและแถบความคืบหน้าไม่ขยับ — เดิมส่งไฟล์ทั้งก้อนรวดเดียวใน request เดียว ตอนนี้ทยอยส่งทีละส่วนตามงบเวลาเท่ากับขั้นตอนอื่น รายงานความคืบหน้าและเวลาที่เหลือตามจำนวนข้อมูลที่ส่งไปจริง และกลับมาทำต่อจากส่วนเดิมได้ถ้าถูกตัดกลางคัน
* แก้ข้อความ "งานหยุดค้าง (ไม่มีความคืบหน้าเกิน 5 นาที)" ที่ขึ้นทั้งที่ยังอัปโหลดอยู่ — ตัวจับงานค้างนับเฉพาะตอนตัวเลขเปอร์เซ็นต์ขยับ จึงเข้าใจผิดว่าการอัปโหลดที่ใช้เวลานานคืองานที่ตายแล้ว
* ลดภาระเซิร์ฟเวอร์ระหว่างงานที่ใช้เวลานาน — หยุดส่ง request ซ้ำซ้อนตอนที่มีตัวประมวลผลทำงานอยู่แล้ว และลดความถี่การถามสถานะจากหน้าเว็บลงเมื่อสถานะยังไม่เปลี่ยน
* ลดหน่วยความจำที่ใช้ตอนอัปโหลด — ส่งข้อมูลจากไฟล์โดยตรงแทนการอ่านทั้งส่วนเข้าหน่วยความจำก่อน
* เพิ่มช่องตั้งชื่อโฟลเดอร์ใน Bucket แยกของแต่ละ provider (เว้นว่างไว้จะใช้ insightx-migrate เหมือนเดิม) ใส่โฟลเดอร์ซ้อนได้ เช่น backups/production

= 0.1.0 =
* First release — export/import ทั้งเว็บเป็นไฟล์ .wpress เดียว (ฐานข้อมูล + wp-content) พร้อม clean-then-restore ตอน import และแทนที่ URL/path/table-prefix อัตโนมัติ
* หน้าข้อมูลสำรอง (Backups) เก็บสำเนาทุกครั้งที่ export ดูรายการ/กู้คืน/ดาวน์โหลด/ดูเนื้อหา/ลบได้จากหน้าเดียว
* เชื่อมต่อ S3-compatible storage หลายเจ้าพร้อมกัน (Amazon S3, Minio, Garage, Cloudflare R2, DigitalOcean Spaces, Google Cloud Storage)
* ตั้งเวลา backup อัตโนมัติผ่าน WP-Cron (รายวัน/รายสัปดาห์/รายเดือน)
* Find & Replace ข้อความในฐานข้อมูลตอน export ได้หลายคู่
* ศูนย์รีเซ็ต (Reset Hub) — ล้างปลั๊กอิน / รีเซ็ตธีม / ล้างคลังสื่อ / รีเซ็ตฐานข้อมูล / รีเซ็ตทั้งเว็บไซต์ พร้อมยืนยันด้วยรหัสผ่านก่อนทำรายการทุกครั้ง
* รองรับ WP-CLI: `wp isx export` / `wp isx import <file>` / `wp isx providers`
